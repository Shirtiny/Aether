# 提供商 / 账号 Turn-State 票据采集与 Codex 号池覆盖

默认关闭；不需要数据库迁移或新增环境变量。部署不会自动替用户选择覆盖来源。

## 上线后配置

1. `/admin/providers` → 编辑需要采集的**来源渠道** → 开启 **Turn-State 票据定时采集**。不再限定聪明渠道；可同时开启多个来源，各自独立采集。
2. 逐行填写模型名，必须与目标号池**最终发往上游**的模型名一致（不是客户端别名）。只采集填写的模型，不扫描全部模型。
3. 来源渠道需处于启用状态，有启用的 `openai:responses` HTTP(S) 端点和可用密钥，且上游成功响应必须返回 `x-codex-turn-state`。复用该渠道的认证、代理和端点配置；无需复制密钥或手工粘贴票据。仅支持聊天补全而不支持 Responses 的渠道不能用于采集。
4. 目标 **Codex 号池 → 高级设置 → Turn-State 票据覆盖来源**，选择上述渠道并保存。例如号池 `e7db605a-c99c-431e-bb23-389b36626890` 可选择「聪明」，其他号池可选择其他来源。
5. 不需要覆盖时选择 **关闭（不覆盖）**。这不会停止来源渠道采集；要停止付费采集请求，请同时关闭来源渠道的采集开关。

下拉框只列出已启用采集且父提供商启用的来源，区分「提供商 · 名称」和「账号 · 提供商 / 账号」。未启用采集的提供商/账号不列入选项；已选来源关闭采集、被删除或加载失败时，在下拉框外提示不可用并保留原配置，不会自动切换来源。

### 单个账号作为来源

1. 在号池账号列表或提供商密钥列表中编辑账号，开启 **账号 Turn-State 票据定时采集**，填写模型并保存。OAuth 账号和普通 API Key 均支持，使用所属提供商的 Responses 端点与该账号的认证/代理。
2. **账号采集与账号是否参与普通请求调度独立**。可以让账号保持停用，仅开启采集；不会自动启用账号。父提供商必须启用，且有启用的 Responses 端点。过期/已标记 OAuth 失效或不允许该模型的账号会记录采集失败，不会换其他账号。
3. 在目标 Codex 号池的「Turn-State 票据覆盖来源」中选择该账号。可跨提供商选择；无需开启来源提供商的提供商级采集。若两个级别都开启，会分别采集、分别计入上游用量。
4. 账号采集同样每模型 40 分钟一次、后台每 15 秒检查，缓存及调度按提供商 ID + 账号 ID + 模型隔离。关闭账号采集、停用父提供商、删除账号或移除配置后清除对应缓存；正常情况下一个扫描周期内停止覆盖，正在请求时等待请求结束。
5. 编辑账号时可在采集开关下查看状态；只返回结果、时间及长度，不返回完整票据。**票据长度与请求成功不能证明账号长期可靠，也不能证明票据可跨模型/账号复用。**

## 查看采集状态

编辑来源渠道，在「Turn-State 票据定时采集」下面查看「采集状态」。按模型显示最近尝试/成功时间、最近结果、失败原因、本地有效票据长度、到期时间和下次尝试时间，不显示票据正文。

- 打开编辑窗口时读取一次；点击「刷新状态」重新读取缓存，**不会发起采集或重置 40 分钟间隔**。
- 只显示已保存的配置，未保存的开关/模型修改不会影响状态。时间使用浏览器时区。
- 采集开关开启不代表已取得票据。最近一次刷新失败与旧票据仍有效可以同时出现。
- 缓存读取失败会显示状态不可用，不显示为成功；任务超时或进程中断不会永久显示「采集中」。
- 老版本只保存票据、不保存采集结果。升级后，只有调度标记但没有结果的模型显示「等待下次调度（旧版未记录结果）」，下一次采集后会有详细结果。

### 采集失败排查

`HTTP 200` 只代表对话响应成功。当前定时采集器通过 HTTP Responses 采集，因此来源必须在 **HTTP 响应头** 返回有效的 `x-codex-turn-state`。如果只返回 SSE 对话事件、没有该响应头，状态会明确提示缺少响应头；此时需要来源支持生成并透传该头，或使用确实支持票据的来源/端点。Aether 不会从任意文本猜测、生成假票据，也不会把普通对话成功标成采集成功。

2026-09-19 对聪明渠道进行短请求诊断时，`gpt-5.6-sol` 和 `gpt-6-astra` 的 HTTP Responses 均返回 200 及正常完成事件，但响应头和事件均未提供票据；WebSocket 升级虽成功，随后返回 `1011 upstream websocket proxy failed`。因此该来源当前的实际采集失败尚不能宣称已解决，需要来源透传配置或此前成功请求的脱敏样例继续定位。未修改来源配置或线上服务。

官方直连诊断还确认 WebSocket 可在 `codex.response.metadata.headers.x-codex-turn-state` 返回票据（部分客户端代码使用 `response.metadata`），而不是握手头；当前定时采集器不走 WebSocket，不能把仅有 WS 元数据票据的来源标成 HTTP 采集成功。2026-09-19 的对照请求显示官方简短 HTTP 请求也能返回票据，因此并不要求多轮对话。

### 提供商 Key 测试是否覆盖

Codex 号池的 Responses / Compact Key 测试走与正式请求相同的覆盖链路。直接测试和号池测试均会按已选来源及最终上游模型使用有效缓存，不依赖会话身份合成开关；关闭、来源不匹配或没有有效票据时不覆盖。查看采集状态和执行 Key 测试不会强制刷新采集票据。

## 行为与边界

- 缓存、采集锁和刷新标记都按**来源渠道 + 模型**隔离。同一来源可供多个号池使用；账号来源与提供商来源分别隔离，不同来源即使模型名相同也不混用票据。不做模型前缀匹配、别名兜底或其他来源兜底。
- 每个来源的每个已配置模型 **40 分钟最多一次**采集。后台每 15 秒检查，一次处理每个来源的一个到期模型；首次多模型采集依次进行。最多并行处理 4 个来源，一个来源失败不影响其他来源。繁忙/慢请求时扫描会延后。
- 共享锁和模型级调度标记防止多实例、重启或失败造成重复付费请求。失败仍保留 40 分钟间隔；短时间关闭再开启不会绕过已有刷新标记。
- 每次发送只要求回复 `OK` 的短 Responses 请求，会消耗少量上游额度，不使用用户对话作为探测内容。
- 票据长度不限定 292 字符，接受非空可打印 ASCII，最大 4 KiB。
- HTTP `/responses`、`/responses/compact` 在身份清理和端点 header 规则之后，将同一张来源票据写入请求头 `x-codex-turn-state` 和请求体 `client_metadata["x-codex-turn-state"]`。只要选定来源有对应模型的有效缓存，即使客户端没有回传、没有 `client_metadata`，或旧票据已被身份清理删除，也会补回；已有其他合法元数据保留。直接/号池 Key 测试遵循同一规则。
- WS 每个 `response.create` 在最终模型映射、body 规则和身份清理之后覆盖 `client_metadata.x-codex-turn-state`；已有连接每步读取所选来源的最新缓存。切换或关闭号池来源会按现有目录变更机制使旧绑定失效，避免继续使用旧来源。
- 独立的 `/v1/alpha/search` 目前仍按搜索接口规则清理票据头，不属于上述 Responses / Compact 请求体补回范围；不能把成功的 Responses 样本视为所有接口均已覆盖。
- **覆盖来源开启时，不向客户端回传上游票据**：HTTP 同步/流式成功和错误响应均移除 `x-codex-turn-state`，在端点响应头规则之后执行；WS 普通、批量与终止事件中的协议票据字段也会移除，不改写对话文本、工具参数或用量。策略跟随当前请求/连接选定的号池来源，不依赖本次缓存命中；无有效票据或模型不匹配时仍不回传。关闭覆盖的号池及其他提供商保持原行为。
- 后台 Key 测试的响应头详情同样隐藏上游票据；请求头详情仍可供管理员验证出站覆盖。内部上游审计和 WS 会话绑定保留原始信息，`client_response_headers` 记录过滤后的客户端响应；不会把这类普通账号响应票据写回采集来源缓存。无需新开关、环境变量或数据库迁移。
- **1 小时是本地缓存最大年龄，不是上游有效期保证**。年龄从采集请求开始计算；刷新失败保留尚未过期的旧票据，但不延长其有效年龄。过期、无匹配模型、来源不存在或共享缓存不可用时沿用原请求逻辑，不伪造或借用其他渠道票据。
- 关闭采集、停用/删除来源、移除模型后，后台清除对应缓存，通常约 15 秒内生效；进行中的采集最多等待约 60 秒，多个慢来源时可能更久。不会撤回已经发送的请求。
- 票据仅存入运行时缓存，不写入渠道配置、不返回管理 API、不主动写入采集日志。原有请求用量/调试捕获策略不变。

## 配置字段与旧版迁移

来源渠道：

```json
{"turn_state_collection": {"enabled": true, "models": ["实际上游模型名"]}}
```

目标号池的 `pool_advanced`：

```json
{"turn_state_source_provider_id": "来源渠道的 provider ID"}
```

账号来源配置（同一 `pool_advanced`）：

```json
{"turn_state_source_provider_id": "账号所属提供商 ID", "turn_state_source_key_id": "账号 ID"}
```

切换回提供商来源时 `turn_state_source_key_id` 必须清空；关闭时两个字段均为 `null`。设置账号 ID 但不设置提供商 ID 会被拒绝。选择的账号失效、删除或无票据时不会回退到提供商票据。

账号新增/更新 API 使用顶层 `turn_state_collection: { enabled, models }`（`null` 清除配置）。内部复用账号 `fingerprint.turn_state_collection` 元数据，不新增表或环境变量；单独更新该字段保留原有 TLS、客户端、WebSocket 指纹及普通调度开关。管理摘要仅投影采集配置和启用的账号名称/ID，状态查询不触发上游请求。

`turn_state_source_provider_id: null` 或字段缺省表示关闭。旧 `congming_turn_state` 采集配置在未保存前仍可读取，保存渠道后转为通用配置。**旧 `congming_turn_state_override: true` 不再启用覆盖**，必须在目标号池明确选择来源并保存，不会猜测来源。旧版全局票据缓存不复用；新版按来源重新采集。
