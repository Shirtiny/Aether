# 聪明渠道 Codex 票据覆盖

默认关闭；不需要数据库迁移或新增环境变量。本功能部署后还需管理员开启，不自动修改现有渠道/号池。

## 配置

1. `/admin/providers` → 编辑「聪明」渠道 → 开启 **聪明票据定时采集**。
2. 逐行填写要采集的模型名。必须是目标号池**最终发往上游**的模型名，而非客户端别名；不会扫描全部模型。
3. 该渠道需有启用的 `openai:responses` 端点，HTTPS 主机必须是 `sub2.congmingai.com`；复用已有可用密钥、认证、代理及传输配置。不要新增或公开密钥。
4. 目标 Codex 号池（例如 `e7db605a-c99c-431e-bb23-389b36626890`）→ 高级设置 → 开启 **聪明票据覆盖**。

渠道配置保存在 `config.congming_turn_state = { enabled, models: [...] }`；号池配置为
`pool_advanced.congming_turn_state_override = true`。全站仅允许一个采集来源同时启用；检测到多个来源时暂停采集并清除覆盖缓存，日志给出原因。

## 行为

- 每个已配置模型 **40 分钟最多一次**采集。后台每 15 秒检查配置，一次处理一个到期模型；首次多模型采集可能依次间隔 15 秒。共享锁和模型级调度标记避免多实例/重启/失败重复请求。
- 每次采集发送一条只要求回复 `OK` 的短 Responses 请求，会消耗少量上游额度；不会使用用户对话作为探测内容。
- 接受非空、可打印 ASCII 票据，最大 4 KiB（与现有 WS 票据上限一致）；不再要求 292 字符。
- 缓存按模型严格隔离，匹配最终请求体的 `model`。不做型号前缀匹配或跨模型兜底。
- HTTP `/responses`、`/responses/compact` 在现有 turn 身份清理和端点 header 规则之后插入/覆盖 `x-codex-turn-state`，即使客户端没有回传也发送。
- WS 每个 `response.create` 在最终模型映射、body 规则、身份清理之后覆盖 `client_metadata.x-codex-turn-state`，已有连接也读取最新缓存，不依赖握手固定值。
- **1 小时只是本地缓存最大年龄**，来自用户观察，并非验证过的上游保证。年龄从采集请求开始计算；刷新失败不覆盖旧票据，也不延长其有效年龄。过期、无匹配模型或共享缓存不可用时沿用原请求处理逻辑。
- 关闭号池开关恢复原逻辑。关闭采集开关、停用来源或移除模型后，后台通常在 15 秒内停止对应覆盖；正在采集时需等待请求结束（最多约 60 秒）。正在发送的请求不撤回。
- 票据仅保存在运行时缓存，不写入提供商配置、不返回管理 API、不主动记录到采集日志。原有请求用量/调试捕获策略不变。

## 验证

本地测试使用内存目录、内存缓存及模拟采集，不请求生产渠道。上线前需另行授权部署；上线后的真实上游兼容性、票据有效期仍需验证。可查看后台任务 `codex.congming_turn_state.worker` 和 `congming turn-state` 日志（只记录模型、来源和结果，不包含票据）。

后端 `congming_turn_state` 相关 14 项测试通过；会话身份、WS runtime、Codex planner 三组回归分别 40 / 43 / 42 项通过。未进行生产采集、数据库修改或服务部署。
